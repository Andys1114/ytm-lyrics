# 搜索前统一繁简，视频不附带发布者

网易云音乐、QQ 音乐和 LRCLIB 共用同一份查询预处理。自动查询、手动搜索和队列预载都适用。

- 使用离线 OpenCC4j 1.14.0 将搜索字段中的繁体转成简体。
- 自动查询和选词框预填会去掉 YTM 的「（合作音乐人：…）」括注。例如「日不落 (Live)（合作音乐人：甲）」用「日不落 (Live)」查询，仍保留现场版标签。比较候选时也忽略这类括注。
- YTM 元数据用于生成搜索词时，将歌名、歌手、专辑里的 `、` 和 `和` 换成空格；例如 `甲、乙和丙` 变为 `甲 乙 丙`。自动查询、队列预载和选词框预填词使用同一规则。
- 音频仍使用歌名与歌手；宿主明确标记为普通 MV（OMV）或用户视频（UGC）时，自动查询只用歌名，不附带发布者。手动搜索框的默认词也遵守此规则。
- 手动输入的搜索词只做繁简转换，保留原有标点和用户填写的歌手或括注。
- LRCLIB 的精确查询需要歌手。视频或没有歌手信息时直接走标题搜索，不发送 `artist_name`。

歌曲标题、歌手和专辑的匹配比较也视繁简字形为等价。原始歌曲信息、来源返回的歌词、候选 ID、手动绑定键与同步偏移均不改写。仅凭视频标题不能确认演唱者；没有直接匹配时，按[自动择优规则](usage.md#自动择优算法)检查专辑、时长或多个来源的歌词时间轴。

## 类型来自实际播放项

固定 YTM 9.41.52 / 94152240，在 `acaf.n()` 构建媒体元数据时读取 `hey.c.hP().l()` 的实际播放项，通过所选 watch endpoint 的 `hlk.H()` 获取类型，将原始数值附加到同一次媒体元数据发布。队列预载读取各条目的当前所选 endpoint，不把私人上传标志当成视频标志。

ATV 与私人上传音轨识别为音频；OMV 与 UGC 识别为视频。其他宿主类别、未知值和无法确认的类型保留原查询语义，不根据标题或缺失专辑猜测。已有明确媒体类型不会被较旧的队列信息覆盖。

## 自动缓存重新查询，绑定继续沿用

自动候选池策略升级为 `automatic-v3/<来源顺序>`，旧策略的候选池不再阻止新查询。缓存的存储格式、24 小时有效期及容量限制不变；手动绑定、来源开关与每曲偏移不迁移、不清除，旧绑定仍按原来源和原歌曲 ID 补取。

## 手机检查

1. 播放繁体歌名／歌手的音频，确认能找到简体元数据候选，原曲信息和歌词显示不被强制改为简体。
2. 播放发布者与歌手不同的 MV／用户视频，打开手动搜索，默认关键词应只有简化后的标题；音频默认词仍包含歌手。
3. 手动输入繁体关键词，确认查询可用；重新播放原有绑定歌曲，确认绑定和偏移继续沿用。

单元测试使用自写元数据和可替换 transport，不访问真实歌词来源。电脑测试与 APK 构建不代替手机上的 Hook 验收。
