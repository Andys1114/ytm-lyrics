# 0.4.0：按播放队列预载歌词

> 本页记录 0.4.0 的实现与当时入口；当前设置入口见 [使用说明](usage.md#播放列表预载)。

2026-10-22，用户要求支持根据播放列表预载歌词。采用默认开启、接下来 3 首的滚动窗口，避免一次请求整个长歌单。手机安装与验收由用户负责。

## 使用

覆盖安装 `dist/ytm-lyrics-0.4.0-debug.apk` 并重新打开 YTM。播放歌单后，进入“来源”，查看“预载接下来 3 首歌词”及进度。切歌命中时状态显示“已命中播放列表缓存”。关闭开关停止后续预载；该开关不删除已有缓存或手动绑定。

## 队列来自实际 YTM 发布入口

对本机 9.41.52（94152240）APK 静态分析确认：`heo.j()` 根据 `abfn` 当前队列及随机／自动播放状态，生成并调用平台 `MediaSession.setQueue`。平台 QueueItem 的 MediaDescription 没有歌曲 mediaId 或完整时长，不能仅凭系统描述直接自动匹配。

`QueueAdapter` 在该发布方法执行后读取当前平台队列，按 queueId 与原队列模型对应，保留实际发布顺序。固定模型 `hxg.h/g` 提供歌名／歌手，`hxj.t` 提供视频标识，`m` 提供队列标识；仅处理该版本并只读原对象，不修改队列或播放状态。反射失败只记录原因，不影响原有当前歌曲取词。

当前歌曲可能没有标准 MEDIA_ID。`QueuePlan.cacheIdentity` 用活动队列条目加歌名／歌手校验，或唯一同名同歌手条目，取得只用于自动缓存的稳定视频 ID；原 `Song.key()` 与手动绑定键不变。无法定位或名字歧义时不猜第一项。重复条目、当前歌曲及无完整歌名／歌手的条目不占预载窗口。

平台接口说明见 [MediaController.getQueue](https://developer.android.com/reference/android/media/session/MediaController#getQueue()) 与 [MediaSession.setQueue](https://developer.android.com/reference/android/media/session/MediaSession#setQueue(java.util.List%3Candroid.media.session.MediaSession.QueueItem%3E))；具体模型映射依据本机 APK 的静态代码，而非这些平台文档推断。

## 缺少时长先保存候选，不提前误配

后台使用现有来源和 Resolver 查询候选，不伪造队列时长。候选池包含逐字、逐行和来源译文，切歌后根据真实元数据运行同一 Matching 排序。缓存命中且来源查询完整时不重复联网；部分来源失败时先显示已有可靠缓存，再正常查询。重试强制联网。手动绑定分支始终先于自动缓存，仍按原来源原歌曲 ID 增强。

`PreloadCache` 使用 YTM 私有、独立的 SharedPreferences；缓存签名包含自动选择版本和已启用来源次序。有效期 24 小时，最多 30 个歌曲池，JSON 内容总量不超过 4 MiB，超限按写入时间淘汰旧池。空查询不抹掉已有内容；损坏条目只删除本条自动缓存，不触碰手动绑定或来源设置。

## 受限后台任务与取消

`PlaylistPreloader` 只用一个后台线程，顺序请求已启用来源；当前歌曲查询和人工搜索期间暂停后台计划，前台不排在预载线程后等待。队列、来源或前台状态变化使用代次取消，迟到结果不写新计划。单次来源请求受既有超时控制，取消在来源返回／后续来源边界生效。

相同队列发布不会重复提交任务；失败／无候选的歌曲有 5 分钟重试冷却，后续计划变化时才再次尝试，不做轮询重试。已存在且可用的绑定或候选池跳过网络。

## 验证与手机验收

电脑测试覆盖队列顺序／去重、随机后的新计划、活动 ID 与无 MEDIA_ID 映射、歧义不猜测、单线程与窗口上限、前台优先、取消迟到结果、来源改变、冷却、24 小时过期、30 首上限、损坏恢复、绑定隔离及开关持久化。

集成测试将模拟的原生队列接入真实 Resolver、候选序列化与持久缓存，再以缺少 MEDIA_ID 但含真实播放时长的当前歌曲命中并自动选择，断言不再次取词。测试不替代 Android 中实际 Hook 的验收。

用户在手机上检查：

1. 播放一个至少 4 首的歌单，“来源”中能出现预载进度，而非一直等待队列。
2. 预载完成后切到下一首，看到缓存命中，歌曲版本、逐字与译文正确。
3. 调换后续歌曲／打开随机播放，检查窗口跟随实际顺序；旧请求不显示成当前歌。
4. 关闭预载、切换来源、重启 YTM，检查开关保存、旧来源缓存不误用，手动绑定仍保留。
